# AFDConnectorBase 接口决策表

本文档记录 `AFDConnectorBase` 当前接口约定，以及两个现有 connector
`P2PAFDConnector` 和 `CAMP2PAFDConnector` 对每个接口的实现现状、入参类型、
出参类型和待决策结果。

决策状态取值：

- `Pending`：尚未决策。
- `Partial`：部分内容已决策，其余内容继续待决策。
- `Keep`：保持当前接口。
- `Change`：修改当前接口。
- `Implemented`：已决策并已在代码中实现。
- `Remove`：删除或替换当前接口。
- `Split`：拆分成更清晰的接口。

类型说明：

- `TensorLike`：当前代码没有定义专门类型，实际通常是 `torch.Tensor` 或后端
  custom op 返回的 tensor-like 对象。
- `VllmConfig`：上游 vLLM `vllm.config.VllmConfig`。
- `DPMetadataLike`：vLLM `DPMetadata` 或插件自有 `AFDDPMetadata`。
- `dict[int, DPMetadataLike]`：key 是 stage/ubatch id，value 是该 stage 的 DP
  token metadata。

## 当前实际 contract 缺口

| 缺口 | 影响 | 决策状态 | 决策结果 |
|---|---|---|---|
| `is_attn_top_min_size_rank` 被 Attention runner 调用，但没有在 `AFDConnectorBase` 中声明。 | 这是事实上的 connector contract。新 connector 即使继承 base，也可能运行时才暴露缺方法。 | `Pending` | TBD |
| `send_attn_output` 返回值不统一。 | 此前 P2P 返回 `None`，CAMP2P 返回 `(hidden_states, None)`，调用方无法基于 base 类型判断返回形状。 | `Implemented` | 已实现：统一返回 `None`；CAMP2P 不再返回 tuple。 |
| `recv_ffn_output` base 返回 `Any`，但实际语义是 tensor-like hidden states。 | 接口没有明确记录必须返回可继续进入模型 forward 的 tensor-like 对象。 | `Implemented` | 已实现：返回类型收紧为 `torch.Tensor`，并移除未使用的 `handle` 入参。 |
| `AFDConnectorMetadata.connector_data` 是 backend-specific `Any`。 | CAMP2P 强依赖 `CAMP2PAFDConnectorMetadata`，P2P 不使用。通用 metadata 和后端 metadata 混在同一个字段里。 | `Pending` | TBD |
| `AFDRecvOutput` 中大量字段是 CAMP2P/MoE 专属字段。 | 通用 payload 类被 NPU backend 形态牵引，P2P 只使用其中很小一部分。 | `Partial` | 已确认：`AFDRecvOutput` 需要后续重新审视并重构；具体结构和替代方案待决策。 |
| `forward_context.additional_kwargs["afd_metadata"]` 在 Attention 与 FFN 侧放不同类型。 | Attention 侧放 `AFDMetadata`，FFN 侧放 `AFDConnectorMetadata`。同一个 key 的语义被复用。 | `Pending` | TBD |
| 控制面方法未标记 `@abstractmethod`，但默认抛 `NotImplementedError`。 | base 对实现类的约束不够强，缺方法可能延迟到运行时才发现。 | `Pending` | TBD |
| `timeout_ms` 出现在 receive 类接口中，但现有实现没有清晰超时语义。 | API 暗示支持 timeout，但底层当前主要是阻塞式 `torch.distributed.recv` 或 object recv。 | `Partial` | 已实现：从 `recv_attn_output` 删除 `timeout_ms`；其它 receive/control-plane timeout 是否保留另行决策。 |
| `get_connector_rank` 的 `rank` 和具体 connector 的 `world_rank` 并非同一概念。 | 调用方容易误用 rank 概念。需要明确该 helper 是否保留、重命名，或补充 `get_world_rank` 等接口。 | `Pending` | TBD |
